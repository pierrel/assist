#+DATE: 2026-08-25

State: Prepared, not cut over

* Scope

Prepare the Qwen3.8 candidate and evidence without upgrading llama.cpp or
changing the running Qwen3.6 service.  The cutover remains gated on a matched
eval panel and explicit operator action.

* Design

1. Keep Qwen3.6 serving unchanged while the candidate is downloaded and
   checksummed.  The candidate is Unsloth's imatrix =UD-Q4_K_XL= GGUF, pinned
   to Hugging Face revision =4ca720788d1e01f1bff70c033e0d0028fd02e502=.
2. Use one launch profile rather than adding model-specific branches to the
   current Qwen3.6 launcher.  It starts with vision enabled at 32k and a
   1.5 GiB =--fit= margin.  Set =ENABLE_VISION=0= for the text-only 100k/Q8
   gate, then the 128k/Q4 gate.
3. Keep the initial vision tier bounded.  The projector consumes additional
   VRAM, so a measured vision tier is required before increasing its context;
   it does not displace the 128k text target by assumption.
4. Preserve a one-command rollback: removing the systemd override restores
   the existing Qwen3.6 =ExecStart=.

The preparation uses =scripts/serve-qwen38.sh= and
=scripts/llamacpp-qwen38.override.conf=.  They are staged files, not active
service configuration.  [[file:2026-08-25-qwen38-operator-runbook.org][The
operator runbook]] is the required manual sequence.

* Design review notes

- Simplicity: one isolated launcher and one small systemd override avoid a
  conditional rewrite of the live Qwen3.6 script.
- Model fit: Qwen3.8 has 16 full-attention layers, so KV-cache precision is
  the decisive long-context control.  Vision starts enabled at 32k; its
  projector is intentionally disabled for the 100k and 128k text tiers.  No
  MTP draft model is enabled because its growing draft context competes with
  the 128k target.
- User outcome: retain the existing OpenAI-compatible endpoint, model
  discovery, =--jinja= tool calling, and one-slot latency profile.
- Security and liveness: this introduces no listener, credentials, or request
  path.  The existing service continues to own its network bind and GPU until
  the operator's explicit systemd restart.

The Giants row is preserved as a pre-migration finding, not counted as a model

the production tool surface requires.  Repairing that fixture is separate from
the model migration; it must be re-baselined before it can be a candidate gate.

The Qwen3.6 image-input contract also passed =tests/test_image_input_guard.py=
(2/2).  It strips image blocks and sends a clear text notice because the live
text-only server cannot consume them.  This is not a vision quality score.  It
is the pre-cutover invariant: the Qwen3.8 vision smoke and new image eval must
replace this behavior only after the vision-capable provider has passed its own
32k gate.

* Acceptance gate after upgrade

1. Verify full GPU offload and the configured context in the llama-server
   startup log.  =--fit= must not quietly reduce the intended tier.
2. Run the same eight runnable rows at candidate N=3.  Any regression stops
   promotion; repair and re-baseline the historical Giants fixture before using
   it as a candidate gate.  The two current 1/3 rows are known Qwen3.6 failure
   modes, so Qwen3.8 must improve or at least reproduce their observed rate;
   it must not turn any current 3/3 row into a regression.
3. At 100k/Q8, verify long prefills and varied batch shapes.  Then test
   128k/Q4 with a deep fill before using it for Assist.
4. Run vision's image smoke and its dedicated eval at 32k.  Increase its
   context only from measured VRAM and quality results.
5. Run candidate confidence N=5, local review, then stability N=10.  Promote
   only if all deterministic/security rows pass and no row regresses from its
   Qwen3.6 baseline.
