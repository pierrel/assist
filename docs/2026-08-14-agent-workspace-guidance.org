#+title: Main-agent private workspace guidance

* Goal

Improve how the ordinary main agent uses its existing private =/agent= mount.
The model should treat Markdown files there as the durable source of thread
continuity, read the relevant files before relying on conversational recall, and
write a concise status checkpoint after material progress. This increment adds a
=/user= compatibility alias, a visible-main handoff convention, and one stable
frequency-decision tool for occasional private maintenance; it does not alter
worker privileges or the persistence of =/tmp=.

* Scope

- The section is rendered only in the ordinary web-main system prompt, which is
  also the profile used by the current CLI and Assist voice-call paths.
- The existing durable-memory procedure is also clarified for every profile:
  current project progress is thread state, not a cross-thread user fact. When
  a private thread memory is available, it is the place for that state; this
  changes no filesystem capability or worker authority.
- =/agent/memory.md= stays the automatically loaded core thread state. The
  guidance may use =status.md= and =recap.md= as optional Markdown conventions,
  not a rigid required tree.
- Children remain isolated: context and research workers receive self-contained
  briefs and do not mount or write the parent =/agent= directory.
- The model sees =/user= as the sole user-owned file tree. It is an alias for
  the established physical =/workspace= mount, which remains compatible for
  existing implementation and user files; neither path creates a second tree.
- =/tmp= remains intentionally persistent per thread. It holds disposable
  conversions and generated render artifacts, never user deliverables.
- The visible main agent gets a single =should_run_maintenance= tool. It returns
  one durable, retry-stable =thread-checkpoint= decision for a probability; a
  loaded skill owns when it is appropriate to ask and what private Markdown to
  refresh.

* Guidance contract

For a request that may depend on user files, personal information, prior work,
or task state outside =/agent=, the main prompt first requires loading
=grounding=. A private =/agent= read for the ongoing thread remains allowed
before that workflow. For a nontrivial continuation, use the loaded
thread-memory block and inspect =/agent= directly, including relevant supporting
Markdown such as =/agent/status.md=, before treating earlier conversation as
current state. After a material decision,
completed stage, discovered blocker, or useful handoff, update a concise
current-progress Markdown file. Never put user deliverables there, and never
claim a private checkpoint is user work. Tracking current work alone does not
authorize a user-workspace or cross-thread-memory change.

The loaded grounding and research procedures, not the bootstrap prompt, direct
the visible main agent to preserve useful context/research handoffs under
=/agent/context/= or =/agent/research/=. Children remain isolated and return
untrusted evidence; the main agent distills only relevant facts, sources or
paths, uncertainty, and its decisions rather than copying raw task output.

Compaction is a checkpoint opportunity, not a new tool contract. The system
prompt treats the automatically reloaded private memory as durable state after a
summary and directs the agent to read additional private Markdown when it holds
relevant detail. This increment does not claim a particular Deep Agents
compaction hook or force a write at every compaction.

The =maintain-thread-state= skill makes periodic state refresh explicit without
an every-turn prompt requirement. It calls the host tool once with the reviewed
=thread-checkpoint= policy and a 0.25 probability. The host stores the resulting
run/skip result by thread and visible Run, so retries cannot resample or switch
policies. Completion and other machine-initiated turns receive no decision ID.
On run it may update =/agent/status.md= or =/agent/recap.md=; on skip it resumes
the user’s work.

The web-main prompt also has a =Deterministic actions= section: when an existing
artifact or direct operation can produce the requested outcome, use it rather
than reconstructing content from memory, prose, or an approximate edit. This
means direct copy/move operations preserve unchanged bytes, while user-visible
files, directory contents, images, and maps use the available rendering
capability rather than a pasted or summarized substitute. It does not replace
requested user edits with shell operations.

* Eval contract

1. Natural read: preseed =/agent/status.md= with a concrete active next step;
   a natural continuation question must read it and answer from it.
2. Natural write: a substantive project update must leave a concise private
   Markdown checkpoint which records the decision/progress without touching the
   user workspace.
3. Forward-looking compaction probe: force the existing summarization middleware
   at a low message threshold, trace =/agent= reads/writes before and after the
   observed compaction event, and retain the counts in the capture. The natural
   continuation must still use the saved checkpoint. This measures whether the
   guidance causes useful extra state work around compaction rather than assuming
   it does.
4. Deterministic directory boundary: =/user/foo= resolves to the existing
   user-workspace file =/workspace/foo= in local and sandbox backends; render
   routes accept either user path.
5. Deterministic periodic maintenance: the same thread/Run/policy/probability
   returns the same saved decision after retry and process restart; a changed
   probability is rejected rather than re-sampled.
6. Deterministic empty-source recovery: initializing a real, zero-byte memory
   file with =write_file= succeeds through an exact empty-string edit; a
   nonempty file retains its no-clobber error in the user workspace, private
   =/agent= route, and sandbox backends.

All behavioral rows reject URL fetches and stub research. The initial pre-change
read probe established the failure mode; candidate runs begin N=1, then use N=3
only after the oracle is sound and the result is promising.

principle: use exact direct operations instead of recreating existing content
from memory, prose, or approximate edits. For user-visible artifacts, it tells
the agent to use the applicable rendering capability and procedure rather than
a pasted or summarized substitute. It deliberately does not name or boost a
single skill. The first, withdrawn wording named =render= directly: the formerly
0/5 directory-render row was 3/3 and the new natural sandbox row “Make a

Before recovery, the scope row consistently wrote its cross-thread fact with
=write_file= to an already-existing empty =/AGENTS.md=. The tool rejected an
otherwise safe initialization; the model then read a synthetic empty-file
reminder, attempted an impossible edit against it, and falsely reported
completion. The backend now retries that exact case as an empty-string edit,
which cannot overwrite a nonempty file. A separate prompt conflict classified
current project progress as durable repository memory despite the private
workspace contract. The durable-memory procedure now explicitly distinguishes
current thread state from cross-thread facts. Both natural rows passed the
post-fix N=5 panel. These historical failures are not evidence that the
deterministic-actions section caused a regression; the current-panel stability
record is the relevant guard.

After the final private-route recovery was added, the full seven-row panel
passed N=3: all 21 invocations succeeded. The two directly corrected natural
journeys then passed their focused N=10 stability panel (20/20 invocations).
The exact pre-change profile was attempted under the same bounded runner but
did not yield a comparable complete panel, so these are current-profile
stability results rather than a causal baseline comparison.

The post-summary turns relied on the automatically reloaded thread memory and
the framework summary rather than making another explicit private-file call.
The test remains a diagnostic because later models, thresholds, and real long
threads may choose a different mix of explicit reads and writes.

* Review experiments

Pierre proposed strengthening the grounding catalog trigger to “could be
enriched by additional context” and removing the bootstrap Grounding section.
On the actual branch profile, the catalog-only variant bypassed =grounding= and
read the trip file directly. The stronger catalog plus broader bootstrap rule
also regressed the small candidate panel. The original narrower trigger stays;
the loaded skill remains the detailed procedure. With the final wording, the
quick panel was 2/3: local-profile grounding and a grounded task edit passed,
while the trip-notes capability still bypassed the skill and read the file
directly. A dependent context-to-research handoff passed N=1. These are
exploratory results, not parity claims.

* Risks and non-goals

Do not turn every response into a write or introduce a second memory system.
Repository =AGENTS.md= remains the cross-thread facts/preferences layer. The
frequency-decision tool governs periodic recap refreshes but does not create
nightly jobs or force a checkpoint every turn. Location inference is unrelated
evidence grounding work and stays out of scope.
