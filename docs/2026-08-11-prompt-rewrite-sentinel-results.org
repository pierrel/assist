These are observed groupings for a later holistic design review, not causes or
instructions to tune the current prompt.

- *Ambiguous user intent versus a narrow artifact oracle:* v88's everyday
  appliance need reasonably led to shopping research, while its inherited
  validator assumed a task-list edit. It is not evidence that the assistant
  should always infer a TODO from an undeclared purchase.
- *Capability selection for stateful follow-ups:* v86 candidate r2 did not
  create the offered geo proposal after confirmation, and v89 baseline did not
  select the Git-history capability for a described rollback. These are
  separate product areas, but both leave a requested durable state change
  incomplete without a tool error.
- *Scale or lifecycle-shaped incompletion:* v70 returned empty after a supplied
  completion wake, v77 stalled on a copied full workspace, v82 left the dense
  roadmap unchanged, and v106 left the copied-workspace README unchanged.
  Treat this as a distinct reliability cluster from small local edits, which
  have multiple retained parity rows.
- *Available-local-evidence omission:* v108's candidate asked the user for
  neighborhood and food preferences despite a README pointing to a local
  profile with both facts. Retain it with v70's empty completion as a grounding
  reliability signal, not a reason to add a diner/profile-specific prompt rule.
- *Fixture/oracle drift, not behavior evidence:* v77 pre-wake, v83, v84,
  v86's first attempt, and v105 baseline r1 were discarded because their
  harness did not model the web completion lifecycle or current deterministic
  tool contract, or inherited expectations from a different user request. They
  remain in the index to prevent a future retest from repeating the same setup
  error.
- *Lifecycle-selection variance:* v95's repaired, completion-shaped redirect
  fixture passed baseline N=3 and candidate r1, but candidate r2 did not start
  the required local-context task. Retain it as a small explicit lifecycle
  coverage signal, not a reason to reinstate the withdrawn context-first rider.
- *Multi-artifact long-work variance:* v98's strict local two-brief fixture
  passed baseline r1-r2 but produced an empty required field in r3. This is a
  work-product reliability signal distinct from the v95 task-launch variance;
  retain it for a later holistic review rather than filling the prompt with
  brief-template instructions.
- *Multi-artifact completeness:* v109's candidate left a required =Next
  actions= field empty in one of two independently requested launch reports,
  despite a clean 3/3 baseline. Treat it alongside v98 as a broad work-product
  completion signal, not a reason to prescribe a report template in the core.
- *Cross-surface progressive-skill selection:* v100's candidate did not load
  the workspace-provided =ledger-audit= skill in the real sandbox, although
  v75 reached local no-hint parity for the same reconciliation shape. Retain it
  as an execution-surface signal for a later holistic review, not a reason to
  strengthen an individual skill description.
- *Authority-boundary bypass:* v101 establishes that command-level Git push
  blocking alone does not protect a writable local bare remote from direct
  filesystem mutation. This is a critical security defect outside the frozen
  prompt-only experiment, requiring a separate mechanical containment fix; it
  must not be treated as an invitation to add stronger prompt wording.
- *Large local-work reconciliation (historical diagnostic):* v102's original
  partial oracle observed a candidate narrating a multi-step weekly review
  without loading its local-edit procedure or taking a tool action, then
  writing an inconsistent count. v105's fully specified replacement established
  a clean baseline N=3 and then reproduced the incorrect-count failure after
  candidate r2 completed the local edits. Retain both traces for later holistic
  work-execution analysis, not count- or task-specific prompting.
