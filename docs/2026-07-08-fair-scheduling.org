#+TITLE: Fair scheduling / queue management — research must not block testing
#+DATE: <2026-07-08>
#+STATUS: DESIGN — approved direction (Pierre, 2026-07-08). Two phases; Phase 1 (durable
#+STATUS: sub-agent persistence) lands FIRST. NO --parallel change (single slot, single-flight kept).

* The problem (Pierre's words)
"Research frequently blocks my testing." A single long research turn (2026-07-07 peptides
ran 68 min; another 96 min) holds the one llama.cpp slot + the THREAD_QUEUE, and Pierre's
quick TEST turns queue behind it — up to ~an hour.

* The chosen approach — round-robin time-slicing on the single slot (Pierre's design)
Each turn gets a *10-minute active-slot quantum*. When the quantum expires AND another turn
is waiting, the holder is PAUSED at its next superstep (its checkpoint is already durable) and
requeued at the BACK; the next turn runs under the same rule. If NOTHING is waiting, the timer
just re-arms — no pointless pause when the slot is uncontended. A separate *2-hour hard cap*
(the existing watchdog) still KILLS a true runaway. Round-robin, no priority classification —
it doesn't matter that the blocker is a HIGH web turn; every turn cycles.

Rejected earlier options: =--parallel 2= (Pierre: increasing parallel is out of the question;
he'd rather raise the single-slot context) — and it slows both turns on one GPU anyway; a
research wall-clock CAP (Pierre: the long research is legit + wanted, don't truncate).

* Why we are NOT fighting the framework — the current system already does 90% of this
=ThreadQueueMiddleware.after_model= ALREADY reads =handle.expired= (set off-loop by the queue's
watchdog Timer) and raises to yield the slot BETWEEN LLM calls — and it already fires during
=.invoke()= (that's how the current 2h watchdog kills runaway web turns today). So:
- *No =invoke=→=stream= rewrite* (the earlier design review's scary part evaporates — the yield
  point already exists via the middleware hook, live under invoke).
- Pause rides that hook: add a =pause_requested= flag next to =expired=; =after_model= raises
  =ThreadPauseRequested= (non-terminal) instead of =ThreadHoldExpired= (terminal).
- Resume = a fresh run with =input=None= from the durable checkpoint — already proven by
  =invoke_with_rollback= (resumes with =current_input=None=) and HITL =resume_reply=.
- Sandbox = swap-and-reattach-workspace (kill container on pause, fresh on resume; =/workspace=
  + the #179 =/tmp= persist on the host). ZERO =sandbox_manager.py= change; keeps PR #139's
  "container age == slot-hold age" invariant (reap on pause, recreate on resume).

* The load-bearing problem: the expensive work is in a NON-DURABLE sub-agent
Research runs INSIDE a sub-agent, which is ONE giant superstep at the trunk level — so pausing
at the outer turn's boundaries is useless (the whole 68 min is one step there). To pause
research you must pause INSIDE it. But sub-agents today use a NON-durable =InMemorySaver= with a
throwaway =uuid= per dispatch (=checkpoint_rollback.py:214-221=, deliberate for rollback
isolation). A naive mid-sub-agent pause loses its findings and re-runs on resume. Pierre's call:
make sub-agents durably resumable — WITHOUT any lost work — and do it FIRST.

* Phase 1 (DONE — no code change needed) — durable sub-agent resume is ALREADY general
*Finding (verified 2026-07-08, hands-on with a real SqliteSaver): a nested sub-agent paused
mid-run RESUMES from its durable checkpoint on a parent replay, WITHOUT re-running completed
steps — via langgraph's OWN mechanism, no assist change.* Sub-agents inherit the trunk
checkpointer (config CONFIG_KEY_CHECKPOINTER wins over their own saver) so their per-superstep
checkpoints are durable in the trunk store; the nested checkpoint_ns is a deterministic hash of
the parent checkpoint + task position, so a parent replay reproduces it and finds them again.
This is GENERAL — research is NOT special-cased; every sub-agent gets it identically. Pierre's
intent (don't make research special; reuse; REDUCE complexity) is met by RELYING on this, not by
adding a mechanism. Pinned by =tests/test_subagent_durable_resume.py= (asserts completed steps
run exactly once across a pause/resume — the no-lost-work symptom, un-mocked SqliteSaver).

*Rejected (would have INCREASED complexity):* the earlier "3 edits" plan (remove the
RollbackRunnable uuid + carry the checkpointer into the rollback resume + a durable saver for
ALL sub-agents). Hands-on: the uuid hack only fires when =thread_id= is ABSENT (the real nested
web turn always HAS it, forwarded by deepagents' task tool), so it never touches the pause/resume
path; and carrying the checkpointer into a NESTED rollback resume failed with =EmptyInputError=
in an un-mocked test — the rollback path (BadRequestError recovery) is a SEPARATE concern from
pause/resume and is delicate. Touching it would add complexity for a case (eval/emacsos rollback)
that isn't the pain. Left ALONE.

** (historical) the abandoned approach — kept for the record
*Approach A (earlier framing): a real checkpointer for sub-agents via removing the uuid hack.*
Superseded by the finding above: the durability is already there; the removal is unnecessary and
delicate.

What changes (to be pinned by the architect):
- =checkpoint_rollback.py= =RollbackRunnable.invoke= (=:212-221=): today assigns a fresh =uuid=
  + relies on the sub-agent's own =InMemorySaver=. Replace with (a) a DURABLE saver (the trunk's
  SqliteSaver, namespaced ids — one db, durable, isolated) and (b) a STABLE, collision-free,
  RESUME-REPRODUCIBLE id per dispatch (derived from parent thread_id + sub-agent name + a
  per-turn dispatch sequence that replays deterministically from the parent checkpoint), so a
  resume finds the same sub-agent checkpoint rather than starting fresh.
- Rollback still works (rewind the sub-agent's checkpoints by its durable id) — reconcile with
  the reason the fresh-uuid+InMemorySaver existed (checkpoint isolation from the parent).
- Lifecycle: sub-agent checkpoints are durable, so they must be REAPED at turn end (unless the
  turn is paused) to bound db growth — mirror the existing thread checkpoint cleanup.
- Deepagents task-tool dispatch must carry the stable id + support the =input=None= resume path
  into the sub-agent.
Uniform-by-default means the context/research/critique/fact-check/dev sub-agents all behave the
same — one persistence mechanism, no per-sub-agent branches.

Phase-1 risks (for the architect + design review):
1. *Resume-reproducible ids.* The dispatch-sequence id MUST replay to the same value on resume
   (else resume can't find the checkpoint). Ground it in the parent checkpoint, not a live
   counter that resets.
2. *Rollback reconciliation.* The durable saver must not re-break the =EmptyInputError= path the
   fresh-uuid+InMemorySaver was added to fix.
3. *DB growth.* Durable sub-agent checkpoints need reaping at turn end (bounded like the trunk's).
4. *Single shared SqliteSaver connection* (=thread_manager.py:125=, =check_same_thread=False=):
   single-flight (one turn at a time) still holds, so no new concurrent-writer hazard — confirm.
5. *No real search in evals* (Pierre): unit-test the persistence + mock the research sub-agent
   (AGENTS.md #5); don't burn the SearXNG rate limit proving durability.

* Phase 2 — the scheduler (after Phase 1 lands)
- *10-min active-slot quantum, contention-gated.* A per-turn Timer; on expiry set
  =pause_requested= ONLY if =waiter_count() > 0= (lock-free), else re-arm. =after_model= raises
  =ThreadPauseRequested=; the run path catches it OUTSIDE the acquire block, does NOT finalize,
  marks =paused=, reaps the container; the queue requeues the turn at the BACK; resume =
  =invoke(input=None)= + fresh container.
- *2h hard cap that handles paused/queued (Pierre).* The kill must measure CUMULATIVE ACTIVE
  slot-hold, NOT wall-clock-since-start: pause/queue time does NOT count (don't kill a turn for
  time it spent waiting), AND a turn can't dodge the cap by pausing (active hold accumulates
  across resumes). Track accumulated-active-ms on the handle, persisted across pause/resume; the
  watchdog fires when it reaches =DEFAULT_HOLD_TIMEOUT_S=. The container backstop TTL must still
  exceed the ACTIVE cap (the =test_sandbox_per_turn= invariant) — and since a container is
  reaped on pause + recreated on resume, its age is bounded by one active slice, well under it.
- *Round-robin queue.* =_waiters= stays FIFO (a paused turn goes to the back = natural
  round-robin); no priority needed. Event-loop-liveness: =post_message=/=_mark_pending= stay
  =peek_holder=-only; =pause_requested= is a plain =__slots__= attr set off-loop (like =expired=);
  =paused= surfaces to the UI via the =status.json= file, never a loop-side scheduler-map read.

* Top risks (whole design)
1. *Phase 1 resume-reproducible sub-agent ids + rollback reconciliation* — the crux; a resume
   that can't find its checkpoint silently re-runs (the loss we're removing). Architect + design
   review own this.
2. *2h active-hold accounting across pause/resume* — off-by-one here either kills legit long
   research early or lets a runaway dodge the cap.
3. *Event-loop liveness on the scheduler* (2026-06-10 class) — mandatory un-mocked hold-the-slot
   test.
4. *DB growth from durable sub-agent checkpoints* — reap at turn end.
