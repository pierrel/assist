* Objective

P2b.1 makes the future disclosure boundary inspectable before P2b.2 changes any
schema visibility.  It derives the kernel from the real composed request, adds
portable Agent Skills =allowed-tools= declarations to bundled Assist skills,
and fails deterministically when a declaration is stale, misspelled, redundant,
or shadowed inconsistently.

This is the first independently reviewed child of the approved P2b milestone in
[[file:2026-07-26-agent-prompt-architecture.org::#phase-2b-tools-declare][the program design]].

* Design

** One construction-owned grouping

=create_agent= will assemble its supplied tools into two explicit groups before
calling Deep Agents:

1. kernel additions: async lifecycle tools for the async main;
2. non-kernel tools: =AgentSpec.tools= plus Assist's =travel=, =directions=,
   =map_data=, and =read_url= defaults after the existing duplicate removal.

The groups contain the actual tool objects used for that construction.  Tool
names are derived from those objects once; there is no hand-maintained
name-to-origin table in production.  The normal =tools== argument remains the
same ordered concatenation, so LangChain registration and winner order do not
change.

=SmallModelSkillsMiddleware= receives the non-kernel tool names.  On each model
request it derives the profile's exact kernel by taking the actual tools already
present on that final request and excluding those construction-declared
non-kernel names.  =load_skill= and upstream-injected TODO, filesystem, and
delegation tools remain by construction; async lifecycle tools remain because
they were not placed in the non-kernel group.  A non-executable backend already
removes =execute= before this middleware sees the request, so the generated list
cannot claim a schema that is absent.

The explicit no-delegation shape (=async_subagent_tools=()=) is the existing
SMS-triage marker and remains outside P2b.  Its skills prompt receives no kernel
line, and its =load_skill= result omits the newly added =allowed-tools= field,
preserving the prior prompt, loaded skill bytes, and separately gated
=send_reply= surface.  Focused constructor and middleware tests pin both sides
of that boundary, including an unchanged external declaration, without adding
SMS execution to the P0 census.  The packaged read-only backend type
provides source provenance, so triage removes the field only from those sources
without a route/name registry or any rewrite of external skill bytes.

This keeps one authoritative boundary without depending on private compiled
graph fields.  P2b.2 can reuse the same derived set for filtering.  If the real
middleware order does not expose the final request tools here, stop rather than
inspect =agent.nodes= or add a second registry.

** Generated kernel prompt

The skills middleware adds one compact line naming the currently present kernel
tools and stating that declared application tools belong to skills while
migration exceptions remain visible.  The qualification is deliberate:
=notify= remains prompt-owned, and some current profiles register =map_data=
without mounting its web-only owner.  The main Jinja template receives no tool
list.  Startup skill rows remain name plus description only and do not reveal
=allowed-tools=.

P2b.1 does not filter =request.tools= or wrap tool execution.  Apart from the
generated kernel line, all system guidance and every provider-bound tool schema
remain unchanged.

** Portable declarations and precedence

Add =allowed-tools= only to bundled skills that own non-kernel tools.  Use the
same upstream metadata parser used at runtime.  Include all mounted bundled
roots:

- =assist/skills/*/SKILL.md=;
- =assist/main_skills/*/SKILL.md=; and
- =assist/web_skills/*/SKILL.md=.

Validation resolves sources with the existing last-source-wins rule.  A
shadowed declaration contributes nothing; the winning metadata and the body
returned by =load_skill= must come from the same path.  Kernel tools such as
=execute=, filesystem tools, TODO, synchronous =task=, async lifecycle tools,
and =load_skill= are deliberately omitted even when a skill body uses them.

Losing shadowed declarations are ignored, exactly like their bodies and
descriptions.  The shadowing negative fixture changes the /winning/ source's
declaration and proves that the diagnostic names that winning path and bad tool;
it does not reject irrelevant metadata in a losing source.

External domain and embedder skill declarations are recorded by the census but
are not enforced or gated in this child.  That is P2b.3.

* Test and experiment gate

** Deterministic

- The existing P0 census remains 27/27 before implementation.
- Every bundled declaration parses through upstream =_parse_skill_metadata=.
- Each token is one exact current model-visible tool name, exists in a recorded
  real composition mounting that winning skill, and is non-kernel there.
- Every registered bundled non-kernel tool has an owner.  Shared ownership must
  be explicitly justified; accidental multiple winning owners fail.  Ownership
  is global across recorded winning bundled declarations in this declaration
  child.  A profile that registers a tool without mounting its owner is recorded
  for P2b.2 rather than changing the P2b.1-visible surface.
- Misspelled, command-pattern, stale, kernel-redundant, and bad winning-source
  shadow fixtures fail with both the skill path and offending name.
- Generated kernel names equal these exact recorded real-composition sets:

  | Composition | Expected kernel |
  |-------------+-----------------|
  | =web-main-core= and =web-main-full= | =write_todos ls read_file write_file edit_file glob grep execute load_skill start_async_task check_async_task update_async_task cancel_async_task list_async_tasks= |
  | =web-delegate= | =write_todos ls read_file write_file edit_file glob grep execute task load_skill= |
  | =legacy-main= | =write_todos ls read_file write_file edit_file glob grep task load_skill= |
  | =skill-precedence-built-in= and =skill-precedence-embedder= | =write_todos ls read_file write_file edit_file glob grep load_skill start_async_task check_async_task update_async_task cancel_async_task list_async_tasks= |

  The first row is executable async main, the second executable synchronous
  delegate, the third non-executable synchronous legacy, and the fourth
  non-executable async main.  Other fixed-role profiles do not mount skills and
  remain outside P2b.
- Tool name order and canonical provider schema JSON are byte-identical to the
  merged P2 baseline for every recorded composition.
- The census final-boundary assertion proves that no middleware after the skills
  middleware changed =request.tools=.  If a future harness profile introduces a
  downstream tool exclusion, the gate fails until the kernel line is generated
  at an equally authoritative seam.
- The construction trace fails if an application/non-kernel candidate collides
  by name with a framework-injected kernel candidate.  Name subtraction is used
  only after that provenance check proves the winning groups are disjoint.
- The runtime request seam rejects any kernel name that cannot satisfy the
  existing OpenAI/vLLM tool-name contract before interpolating it into the
  system prompt.  Current application/framework collisions are detected by the
  pre-deduplication census.  Future external/embedder collision enforcement is
  deferred to P2b.3; embedders are trusted host code, not model or skill input.
- Existing HITL, URL provenance, read-only, role-omission, and SMS-triage tests
  remain green.
- The explicit no-delegation/triage construction does not emit the generated
  kernel line or expose =allowed-tools= in loaded bodies; its prior skills
  prompt, skill results, and tool surface remain unchanged.

** Behavioral

Pre-register and run the same natural nodes on unchanged merged P2 and the
candidate, N=3 each:

1. implicit main skill loading, because the new kernel line sits in the skills
   prompt immediately before the unchanged catalog;
2. delegate implicit skill loading, because its kernel includes synchronous
   =task= instead of async lifecycle tools; and
3. imminent urgent notification, because =notify= remains the explicit
   prompt-owned exception and its existing urgent-first rule must not regress;
4. the existing suggested/explicit skill-routing case, to distinguish a prompt
   comprehension regression from the harder implicit match; and
5. one ordinary routine request that should neither load a skill nor select a
   work tool, to catch a system-wide tendency to act on the kernel list itself.

The candidate must meet the baseline full-pass count for every node and the
program's 70% natural floor.  This child adds no model step.  A changed tool
choice, missed load, or reordered urgent action is a regression even if the
final prose looks plausible.  P2b.1 does not need the broader P2b.2 disclosure
cohort because no schema is hidden yet.

* Stop gates

- Stop if construction grouping changes tool order, a winner, or any provider
  schema.
- Stop if kernel derivation needs private LangGraph graph/node inspection, a
  copied list of Deep Agents tool names, or a production dependency on EDD.
- Stop if =SmallModelSkillsMiddleware= runs before another middleware can remove
  =execute=, because its generated kernel would not match the final request.
- Stop if any later middleware changes the tool list, or if a framework and
  application candidate share a name.  Do not resolve either problem with a
  copied built-in-name list.
- Stop if winning skill metadata and =load_skill= body precedence differ.
- Stop and report rather than broadening scope if =notify= cannot gain a web-only
  owner without changing urgent or SMS-triage behavior.
- Stop if the new prompt line causes a natural regression that cannot be fixed
  by shortening or clarifying that line alone.  Filtering belongs to P2b.2.

* Non-goals

- No schema filtering, hidden-tool rejection, load state, =ToolMessage.artifact=,
  checkpoint state, or concurrent disclosure behavior.
- No domain/embedder declaration enforcement or tool gating.
- No SMS-triage, memory, research, development-guidance, or skill-catalog lifetime
  change.  The explicit no-delegation profile is excluded from P2b kernel prose.
- No Deep Agents fork, replacement parser, private graph introspection, or second
  tool registry.
- No unrelated cleanup found during review.

* Implementation notes

The hard part is not parsing =allowed-tools=.  Upstream already does that.  The
hard part is naming the kernel from the real final composition without copying
Deep Agents' built-in names or binding Assist to private LangGraph internals.
The construction-group/final-request subtraction keeps that responsibility in
two small existing seams.  The other nontrivial edge is =notify=: its current
always-on urgent-first behavior predates skill ownership, while skill metadata
is checkpoint-cached across normal and SMS-triage constructions.  The stop gate
prevented a cache redesign or an SMS change; the exception is explicit instead.

The longest part was review convergence around the stricter promise that SMS
triage does not change.  Adding frontmatter alters the bytes returned by
=load_skill= even when the prompt and schemas are unchanged.  A first generic
marker approach preserved the new bundled files but could also rewrite a future
external skill using that marker.  The final construction instead reuses a
packaged read-only backend type as source provenance, excludes reserved-route
overrides, and strips the field only for the existing no-delegation profile.
That added two small production seams in =backends.py= and =thread_manager.py=;
it did not add a registry, checkpoint state, tool filter, or SMS-specific tool
behavior.  Repeated review also removed duplicate validation, duplicate tool-name
extraction, and accidental prompt whitespace rather than broadening the goal.
