* Objective

P2b.1 makes the future disclosure boundary inspectable before P2b.2 changes any
schema visibility.  It derives the kernel from the real composed request, adds
portable Agent Skills =allowed-tools= declarations to bundled Assist skills,
and fails deterministically when a declaration is stale, misspelled, redundant,
or shadowed inconsistently.

This is the first independently reviewed child of the approved P2b milestone in
[[file:2026-07-26-agent-prompt-architecture.org::#phase-2b-tools-declare][the program design]].

* Design

** Census-owned classification, no runtime registry

P2b.1 leaves =create_agent='s tool expression and middleware request path
unchanged.  The existing P0 census observes the actual pre-deduplication
=ToolNode= candidates, final model request, and winning skill sources for each
real composition.  It classifies framework-origin TODO, filesystem,
delegation, =load_skill=, and Assist async lifecycle tools as kernel candidates;
the remaining Assist tools are skill-scoped candidates.  Exact expected kernel
sets are pinned for executable and non-executable main, delegate, legacy, and
source-precedence compositions.

This classification exists only in EDD evidence.  Production does not extract
tool names, copy framework names, inspect private graph nodes, or carry a second
registry before P2b.2 needs the boundary for filtering.

P2b.1 adds no SMS-triage-specific production path.  Its prompt, tool set,
routing, permissions, backend types, and access policies remain the merged-P2
ones.  Because the same bundled files are mounted across profiles, their new
standard frontmatter is present if a skill is deliberately loaded or read;
P2b.1 does not interpret it at runtime or grant any authority from it.

** No model-visible kernel until P2b.2

P2b.1 does not change the startup prompt, provider schemas, executable tool set,
or tool ordering.  Startup skill rows remain name plus description only and do
not reveal =allowed-tools=.  A successfully loaded bundled skill returns its
new declaration as ordinary frontmatter in every profile that mounts it.

P2b.2 will generate the model-visible kernel at the same final-request seam that
filters schemas and execution.  Landing the explanation with the behavior keeps
the prompt truthful and avoids a declaration-only line that the small model
mistook for a routing instruction.

** Portable declarations and precedence

Add =allowed-tools= only to bundled skills that own non-kernel tools.  Use the
same upstream metadata parser used at runtime.  Include all mounted bundled
roots:

- =assist/skills/*/SKILL.md=;
- =assist/main_skills/*/SKILL.md=; and
- =assist/web_skills/*/SKILL.md=.

Validation resolves sources with the existing last-source-wins rule.  A
shadowed declaration contributes nothing; the winning metadata and the body
returned by =load_skill= must come from the same path.  Kernel tools such as
=execute=, filesystem tools, TODO, synchronous =task=, async lifecycle tools,
and =load_skill= are deliberately omitted even when a skill body uses them.

Losing shadowed declarations are ignored, exactly like their bodies and
descriptions.  The shadowing negative fixture changes the /winning/ source's
declaration and proves that the diagnostic names that winning path and bad tool;
it does not reject irrelevant metadata in a losing source.

External domain and embedder skill declarations are recorded by the census but
are not enforced or gated in this child.  That is P2b.3.

** Behavioral

The corrected candidate leaves bootstrap behavior unchanged.  Its remaining
model-facing risk is that =allowed-tools= now appears in a bundled skill body
after a successful load.  Run these natural/capability nodes on unchanged
merged P2 and the corrected candidate:

1. implicit main skill loading, which loads a newly declared bundled body and
   then edits the requested Org file;
2. delegate implicit skill loading, which exercises the same body through the
   synchronous delegate composition; and
3. the explicit render-skill case, which loads a newly declared web-only body
   and then uses its application tool.

The candidate must meet the baseline full-pass count for every node and the
program's 70% natural floor.  This child adds no model step.  A missed load,
failure after reading the declaration, or changed tool choice is a regression.
The urgent-notification and ordinary no-tool controls belonged to the removed
startup-prompt experiment; they are not affected by the declaration-only final
candidate and are not pulled into its final gate.

* Stop gates

- Stop if construction grouping changes tool order, a winner, or any provider
  schema.
- Stop if kernel classification needs private LangGraph graph/node inspection,
  a copied list of Deep Agents tool names, or any production dependency on EDD.
- Stop if the declarations or classification alter the startup prompt, final
  provider schemas, tool order, or winners.
- Stop if any pre-deduplication candidates share a name, whether their
  classifications match or differ.  Do not resolve the problem with a copied
  built-in-name list.
- Stop if winning skill metadata and =load_skill= body precedence differ.
- Stop and report rather than broadening scope if =notify= cannot gain a web-only
  owner without changing urgent or SMS-triage behavior.
- Stop if any model-visible kernel prose is needed before P2b.2 can pair it with
  filtering.

* Non-goals

- No schema filtering, hidden-tool rejection, load state, =ToolMessage.artifact=,
  checkpoint state, or concurrent disclosure behavior.
- No domain/embedder declaration enforcement or tool gating.
- No SMS-triage, memory, research, development-guidance, or skill-catalog lifetime
  change.  P2b.1 emits no kernel prose in any profile.
- No Deep Agents fork, replacement parser, private graph introspection, or second
  tool registry.
- No unrelated cleanup found during review.

* Implementation notes

The hard part is not parsing =allowed-tools=.  Upstream already does that.  The
first hard part was classifying the kernel from real compositions without
copying Deep Agents' built-in names or binding production to private LangGraph
internals.  Keeping that work in the P0 census makes the boundary inspectable
without adding runtime machinery before P2b.2 needs it.  The other nontrivial
edge is =notify=: its current always-on urgent-first behavior predates skill
ownership, while skill metadata is checkpoint-cached across normal and
SMS-triage constructions.  The stop gate prevented a cache redesign or an SMS
change; the exception is explicit instead.

The longest part was review convergence around the instruction not to turn this
into SMS-triage work.  Adding standard frontmatter changes the shared skill file
bytes.  An attempted =load_skill=-only rewrite did not preserve direct
filesystem reads and required new profile/source plumbing.  Review removed that
entire approach.  The final child adds no triage-specific production code and
does not change its prompt, tools, routes, permissions, or access policy; the
shared skill metadata is simply the same official file content in every mounted
profile.  Repeated review also removed duplicate validation and accidental
prompt whitespace rather than broadening the goal.  Copilot exposed that the
proposed runtime name extraction mishandled dict-form embedder tools.  The
generated kernel line then caused a measured urgent-notification regression.
The final correction deleted the entire runtime extraction and prompt seam
instead of adding compatibility forms or a =notify= special case.  A local
security probe also reproduced a future embedder tool whose name collides with
a framework tool.  P2b.1's census records that risk; runtime rejection across
external representations remains deliberately scoped to P2b.3.

Review additionally found that the urgent-notification eval accepts a late or
repeated =notify= even though the prompt says first and once.  That is valuable
future eval debt with a risk of overstating urgent-first reliability, but the
corrected P2b.1 candidate has no startup-prompt change and no longer affects the
urgent path.  The experimental validator edit was reverted rather than turning
this child into an urgent-notification cleanup.
