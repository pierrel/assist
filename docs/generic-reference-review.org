* Requested outcome and scope

Main, delegate and researcher agents need a bounded way to retain important
exact text from user and tool context in the existing immutable thread store.
Retrieved source URLs already register automatically. This change must keep
source citation identity, navigation authorization, invalid-reference behavior,
ordinary links/code, current file updates and child completion working.
Registration preserves supplied bytes. It does not establish factual truth,
required-detail coverage, a correct source association or independent verification.

Baseline runtime is merged =c2d27390044bd4013459fae7ccb2ce818bc221ad=.
This is distinct from any unmerged live composition. No live-condition
transfer result is claimed. The frozen prompts/fixtures are in
[[file:2026-11-11-generic-reference-baseline.org][the initial panel]] and
[[file:2026-11-11-generic-reference-panel-r2.org][the tool-output amendment]]. The executable panel is
[[file:../edd/eval/test_generic_reference_binding.py][test_generic_reference_binding.py]].

* Proposed smallest implementation

No runtime implementation exists yet. Reuse
[[file:../assist/thread_datastore.py::class ThreadDataStore][ThreadDataStore]] and its existing immutable =put_text= operation. Add one
model-facing generic registration operation with fixed generic kind plus the
existing get/list/search tools. Keep source-row creation solely in
[[file:../assist/thread_datastore.py::def register_source][register_source]] and the current browser ingestion path.

Bare generic references insert text. Citation-link targets remain restricted
to trusted source rows. Main/delegate file-tool content and edit preimages
need the same generic expansion before effects; the research draft/finalization
boundary remains owned by
[[file:../assist/research_cleanup.py::class ReferencesCleanupRunnable][ReferencesCleanupRunnable]]. Existing child import and result formatting must
carry generic records with their original kind, without promoting text to
source authority. Retrieval tool descriptions explain automatic registration;
the generic tool describes when to preserve important exact text and its limits.

Repeated-pass literal safety is being settled before implementation. The
candidate approach rejects reserved =ref:= syntax in registered generic
values and requires any generic-expanded result to already be stable under a
second dry resolution. An ambiguous substitution must fail explicitly before
file effects. Generic-bearing streamed messages may need buffering until the
whole message is checked; source-only streaming can keep its current behavior.
These are proposed contracts, not verified behavior.
